# Настроение новостей

Реальные новости на русском языке, которые можно прочитать в разном
эмоциональном тоне: радостно, грустно, нейтрально, иронично — или в
своём собственном стиле. Факты (имена, даты, числа, места, цитаты)
при переписывании не меняются — только тон.

Стек: **FastAPI + SQLite** на бэкенде, **чистые HTML/CSS/JS** на
фронтенде, переписывание текста — через **OpenRouter** (модель
DeepSeek).

---

## 1. Как запустить

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# откройте .env и вставьте свой ключ OPENROUTER_API_KEY
# ключ можно получить на https://openrouter.ai/keys

uvicorn app.main:app --reload
```

Откройте **http://localhost:8000** — фронтенд отдаётся тем же
FastAPI-приложением (см. `app.mount("/", StaticFiles(...))` в
`app/main.py`), отдельный сервер для статики не нужен.

При первом запуске, если база пустая, backend сам скачивает свежие
новости из Google News RSS (см. раздел 2) — это может занять
несколько секунд. Обновить ленту вручную в любой момент можно так:

```bash
curl -X POST http://localhost:8000/api/news/refresh
```

**Важно:** песочница, в которой собирался этот проект, не имеет
доступа к `news.google.com` и `openrouter.ai` (сетевой доступ
разрешён только к реестрам пакетов — pypi, npm и т.п.), поэтому
живой фетч новостей и вызов LLM не были протестированы «живьём» в
процессе сборки — только на юнит-уровне (парсинг XML, HTTP-клиент,
проверка фактов). Код использует обычные `httpx`-запросы, которые
на вашей машине с обычным доступом в интернет отработают штатно.

## 1.1. Деплой на Render

В репозитории есть `render.yaml` (Blueprint) — Render сам прочитает
из него настройки сервиса.

1. Залейте папку `news-mood` в свой GitHub-репозиторий.
2. В Render Dashboard → **New → Blueprint** → выберите репозиторий.
   Render найдёт `render.yaml` и предложит создать один Web Service
   (`runtime: python`, `rootDir: backend`).
3. Перед деплоем задайте переменные окружения (Render попросит те,
   что помечены `sync: false`):
   - `OPENROUTER_API_KEY` — ваш ключ с openrouter.ai/keys
   - `APP_URL` — итоговый адрес вида `https://news-mood-xxxx.onrender.com`
     (используется как `HTTP-Referer` в запросах к OpenRouter; можно
     обновить после первого деплоя, когда адрес станет известен)
4. Деплой. Стартовая команда — `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
   (Render пробрасывает порт через `$PORT`, поэтому именно так, а не
   `--reload`, как при локальном запуске).

Без Blueprint — то же самое вручную: **New → Web Service**, Root
Directory `backend`, Build Command `pip install -r requirements.txt`,
Start Command `uvicorn app.main:app --host 0.0.0.0 --port $PORT`.

**Если сборка падает на `pydantic-core` / `maturin` / cargo:**
Render взял слишком новую версию Python, для которой ещё нет
готового wheel-пакета `pydantic-core`, и pip пытается собрать его
из исходников на Rust — а это не работает на read-only файловой
системе Render. В репозитории уже есть `backend/runtime.txt`
(`python-3.11.9`) и переменная `PYTHON_VERSION=3.11.9` в
`render.yaml`, которые фиксируют стабильную версию. Если ошибка всё
равно повторяется — проверьте, что в Environment Variables сервиса
стоит `PYTHON_VERSION=3.11.9`, и передеплойте через
**Manual Deploy → Clear build cache & deploy**.

**Про SQLite на Render:** на бесплатном плане файловая система не
персистентная — она сбрасывается при каждом новом деплое (но не при
обычных перезапусках/простое из-за неактивности). Само приложение
это переживает нормально: при старте оно проверяет, что новостей
меньше 10, и само подгружает свежие из Google RSS. Что теряется —
это кэш уже переписанных версий (`rewrites`), их придётся сгенерировать
заново после следующего деплоя. Если это важно — подключите платный
Persistent Disk (в `render.yaml` есть закомментированный блок `disk`)
и укажите `DB_PATH=/var/data/news.db`.

## 2. Откуда берутся новости

`app/rss_fetcher.py` скачивает и парсит RSS-ленту Google News:

- по умолчанию — общая топ-лента: `https://news.google.com/rss?hl=ru&gl=RU&ceid=RU:ru`
- если задать `GOOGLE_NEWS_QUERY` в `.env` (например, `технологии`),
  используется поиск по теме: `https://news.google.com/rss/search?q=...&hl=ru&gl=RU&ceid=RU:ru`

Из каждого `<item>` берутся: заголовок, ссылка на источник (`link`),
название источника (`<source>`, например «Интерфакс»), дата
публикации и текст — это HTML-описание из `<description>`,
очищенное от тегов через BeautifulSoup. Google News RSS отдаёт
именно короткую выжимку/подводку, а не полный текст статьи —
парсить полный текст с сайтов десятков разных издателей ненадёжно
и почти всегда нарушает их условия использования, поэтому
«исходный текст» в этом приложении — это официальная выжимка
Google News, а по ссылке всегда можно открыть полную статью на
сайте издателя.

Новости сохраняются по `guid` — при повторном фетче дубликаты не
создаются, добавляются только новые записи. При старте backend сам
проверяет, что в базе есть хотя бы 10 новостей, и при необходимости
подгружает их.

## 3. Как устроено хранение данных

SQLite, обычный `sqlite3` из стандартной библиотеки (без ORM —
`app/database.py`). Две таблицы:

```
news
├─ id, guid (уникальный), title, link, source
├─ published_at, original_text, fetched_at

rewrites
├─ id, news_id → news.id, mood
├─ rewritten_text, fact_check_json, created_at
└─ UNIQUE(news_id, mood)
```

Переписанный текст кэшируется: при повторном запросе той же новости
в том же настроении LLM не вызывается повторно — результат берётся
из `rewrites`. Свой (произвольный) вариант тона кэшируется по точному
тексту, который ввёл пользователь.

## 4. Как переписывается тон

`app/rewriter.py` формирует запрос к OpenRouter
(`POST https://openrouter.ai/api/v1/chat/completions`), модель по
умолчанию — `deepseek/deepseek-v4-flash` (задаётся в `.env`, полный
список моделей DeepSeek — на `openrouter.ai/deepseek`).

Системный промпт явно требует:
- сохранить все факты (имена, даты, числа, статистику, места, суть цитат);
- менять можно только грамматическую форму слов и стиль изложения;
- запрещено придумывать новые факты или убирать существующие;
- ответ — только переписанный текст, без пояснений.

Для «радостно / грустно / нейтрально / иронично» есть готовые
описания стиля (`MOOD_PROMPTS`). Если пользователь вводит свой
вариант в поле «свой стиль…», он подставляется в промпт как есть
(`в стиле: <текст пользователя>`).

---

## 5. Как проверяется сохранение фактов

Точных гарантий того, что LLM ничего не исказит, не даёт никто —
поэтому после каждого переписывания `app/fact_checker.py` делает
**автоматическую эвристическую проверку** и результат виден в
интерфейсе (зелёный бейдж «факты сохранены» / жёлтый «возможны
расхождения»):

1. Из **оригинального** текста регулярными выражениями извлекаются:
   числа/проценты, даты и годы, прямые цитаты в кавычках («…» и
   "…"), а также стемы (первые 4–5 букв) слов с заглавной буквы —
   грубое приближение к именам собственным.
2. Каждый найденный «факт» ищется в переписанном тексте.
   Для имён собственных сравнивается именно стем, а не всё слово —
   из-за русских падежей («Путин» → «Путина», «Путиным») точное
   совпадение ненадёжно, а стем обычно сохраняется при склонении.
3. Если что-то не найдено — это попадает в список `missing` и
   показывается прямо под переписанным текстом, с оценкой (score)
   от 0 до 1.

Это не полноценный NLP-фактчекинг, а прозрачная и объяснимая
эвристика на regex: она не поймает переформулировку смысла цитаты,
но надёжно ловит пропавшие числа, даты и имена — самые частые и
самые вредные искажения при «эмоциональном» переписывании.
Логика проверки полностью в одном файле (`app/fact_checker.py`),
её можно прочитать и проверить вручную.

---

## 6. Использование AI

- **OpenRouter → DeepSeek (`deepseek/deepseek-v4-flash` по умолчанию)** —
  единственная модель, которая реально переписывает текст новости
  под выбранный тон. Вызывается из `app/rewriter.py`.
- Никакая другая модель факты не «придумывает» и не фетчит новости —
  сам список новостей приходит из Google News RSS без участия LLM.
- Автоматическая проверка фактов (раздел 5) — это обычный код
  (regex), а не ещё одна модель, специально чтобы результат был
  детерминированным и проверяемым.

## 7. API

| Метод | Путь | Описание |
|---|---|---|
| GET  | `/api/news` | список новостей (грид) |
| GET  | `/api/news/{id}` | одна новость целиком |
| POST | `/api/news/{id}/rewrite` `{ "mood": "радостно" }` | переписать / получить из кэша |
| POST | `/api/news/refresh` | подтянуть свежие новости из Google RSS |
| GET  | `/api/moods` | список встроенных настроений |

## 8. Структура проекта

```
backend/
  app/
    main.py          FastAPI-приложение, роуты, раздача фронтенда
    config.py         настройки из .env
    database.py        sqlite3: схема, соединения
    rss_fetcher.py      получение новостей из Google News RSS
    rewriter.py         вызов OpenRouter, промпты по настроениям
    fact_checker.py     эвристическая проверка сохранения фактов
  requirements.txt
  .env.example
frontend/
  index.html
  style.css
  app.js
render.yaml          конфигурация деплоя на Render (см. раздел 1.1)
```
